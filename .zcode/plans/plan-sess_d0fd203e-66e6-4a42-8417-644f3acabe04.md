# Role-based data access restructure — CafeFlow

**Principle:** the client (restaurant owner) owns all business detail (orders, shifts, terminal sales, reports). Super Admin sees only aggregate/platform metrics, plus a **time-boxed, reason-required, fully audited "support access" grant** to view one specific client's order/sales detail when support is genuinely needed. No POS app changes.

## 1. Schema migration (`prisma/schema.prisma` + mirror DDL in `/supabase/migrations`)
- Add nullable `deviceId` + relation + index to **Sale, Order, Shift, Expense** (sync handlers already know the device; this enables "sales by POS terminal" with zero POS changes; historical rows stay null → UI shows "Unattributed").
- New **SupportGrant** model: `adminProfileId, clientId, reason (required), createdAt, expiresAt, revokedAt?` — the break-glass permission.
- New **AuditLog** model: `actorProfileId, actorEmail, action, targetType?, targetId?, clientId?, metadata?, createdAt`.
- Run `prisma migrate dev`; confirm build runs `migrate deploy` before `prisma generate`.

## 2. Sync handlers stamp the terminal (`src/lib/services/pos.ts`)
- Add `deviceId: ctx.device.id` to the `create` calls in `syncSales`, `syncOrders`, `syncShifts`, `syncExpenses`.

## 3. Super Admin → aggregates only
- **Delete pages:** `src/app/admin/sales/page.tsx`, `src/app/admin/orders/page.tsx`, `src/app/admin/orders/[id]/page.tsx`; remove Sales/Orders from `ADMIN_NAV` (`src/components/dashboard/shell.tsx`) and any inbound links.
- **Admin dashboard** (`src/app/admin/page.tsx`): remove the "Latest POS terminal activity" card (recent shifts with cashier names, net sales, cash differences; recent expenses) and its `listRecentShifts`/`listRecentExpenses` calls. Keep "Shifts synced"/"Expenses synced" count cards; add "Active POS terminals (24h)" (devices ACTIVE + `lastSeenAt` ≥ now−24h — already updated per request at `pos.ts:223`) and "Shifts synced (24h)". Since POS only uploads closed shifts, "active shifts" is surfaced as "shifts synced in last 24h" (web-only scope, per your choice).
- **`src/lib/services/dashboard.ts`:** delete `listRecentShifts`/`listRecentExpenses`; add `getAdminTerminalActivity()` (SQL counts). Keep all existing aggregate functions (overview, 14-day trend, payment split, top restaurants, client revenue ranking).
- **`src/lib/services/clients.ts` `getClientDetail`:** replace the "load every sale row + 200 order ids per restaurant" aggregation with SQL `groupBy` aggregates (per-restaurant today/month sales, total orders, sales summary). Keep the login-accounts list (email/name/status/lastLoginAt) — required for the admin "change client password" feature, which stays.
- **Keep** `/admin/reports` (lifetime + 30-day aggregates, client revenue ranking) — allowed aggregate metrics.

## 4. Support access hybrid (privacy by default, audited support)
- New `src/lib/services/support.ts`: `createSupportGrant(adminProfileId, clientId, reason, hours≤24)`, `getActiveGrant(adminProfileId, clientId)`, `revokeSupportGrant(...)`, `logAudit(...)`; creating a new grant auto-revokes prior ones for the same admin+client.
- New guard `requireSupportAccess(user, clientId)`: SUPER_ADMIN **plus** an active, non-revoked, non-expired grant — used by all support detail views; every view writes an AuditLog row.
- Admin UI:
  - On `/admin/clients/[id]`: a "Support access" card — request grant (reason + duration), show active grant with countdown, revoke button. New API routes `POST/DELETE /api/admin/support-grants`.
  - Grant-scoped, read-only pages (404/redirect without an active grant, banner "Support access for {client}, expires {time} — all views are logged"):
    - `/admin/clients/[id]/orders` — paginated order list (reuses `listOrders` scoped to that client's restaurants)
    - `/admin/clients/[id]/orders/[orderId]` — order detail with line items (ownership-checked to that client)
    - `/admin/clients/[id]/sales` — sales list (reuses `listSales` scoped)
  - No platform-wide order/sales browsing remains — detail is only ever one client deep, grant-gated.
- New `/admin/audit` page: paginated audit log (actor, action, target, client, time, metadata).

## 5. Client (owner) → full detail, the inconsistency fixed
- New `src/lib/services/shifts.ts` (all queries scoped by session `clientId` / `assertRestaurantAccess`):
  - `listShifts({restaurantIds, from, to, page, pageSize})` — completed shifts with totals.
  - `getShiftDetail(...)` — cash reconciliation (opening/closing/expected/difference), linked expenses (`Expense.shiftLocalId`), and **shift transactions** = orders within `[openedAt, closedAt]` (device-matched where deviceId known).
  - `getTerminalBreakdown({restaurantIds, from, to})` — sales/orders grouped per device + "Unattributed" bucket.
- New client pages (guarded by `requireClientPage`, owner-scoped):
  - `/client/restaurants/[id]/shifts` + `/client/restaurants/[id]/shifts/[shiftId]` — shift list & detail.
  - `/client/shifts` and `/client/orders` — cross-restaurant views (owner's full estate) linking into existing detail pages; orders history already exists per restaurant and stays.
  - `/client/reports` — date-range picker: daily sales table, payment split, sales-by-terminal breakdown, per-shift summary, per-restaurant comparison.
- Enhance existing pages: restaurant workspace gets a Shifts link + "active terminals (24h)" status; sales page gets a daily-sales summary table and by-terminal breakdown card.
- API parity: `GET /api/client/shifts` (list + `?shiftId=` detail), following the existing `/api/client/orders` pattern. `/api/client/*` routes stay owner-scoped as today.
- UI copy marks shift pages "Completed shifts" (open shifts aren't uploaded; terminal "last seen" shows live activity).

## 6. Security fixes while in there
- Admin **temporary-password** reset (`src/app/api/admin/clients/[id]/password-reset/route.ts`): bump `tokenVersion` so prior sessions die — currently only the email-link path does this.
- Delete stray backslash-named duplicate route artifacts under `src/app/api/pos/` (e.g. `expenses/sync/\route.ts`).

## 7. Verification
- `prisma migrate dev` + `npm run build` green.
- Manual matrix: CLIENT can open own orders/order-detail/shifts/shift-detail/reports and **cannot** reach another tenant's (ownership check returns identical not-found); SUPER_ADMIN dashboard shows counts only; `/admin/sales`, `/admin/orders` are gone; support flow: no grant → blocked, active grant → works + audit rows written, revoked/expired grant → blocked; password temp-reset invalidates old sessions.

**Notes:** no POS app changes; per-terminal attribution applies to newly synced data only.
